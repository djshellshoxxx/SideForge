You are building a production-quality Windows VST3 audio plugin from scratch. The plugin is an advanced sidechain processor combining traditional sidechain compression, drawable rhythmic volume shaping, multiband processing, and intelligent spectral ducking.

Working name: SideForge
Framework: JUCE with CMake
Language: modern C++20
Primary target: Windows 10/11 x64, Visual Studio 2022, VST3
Optional target: Standalone build for development and testing
Do not add macOS, Linux, AU, or AAX support.

Work autonomously. Do not stop to ask routine implementation questions. Make sensible engineering decisions and document them. Do not attempt the entire implementation in one uncontrolled pass: build it incrementally, compiling and testing after every major phase. CORE PRODUCT

SideForge should provide three blendable processing engines:

1. Compressor Engine
- External or internal sidechain
- Threshold
- Ratio
- Soft/hard knee
- Attack
- Hold
- Release
- Range/maximum gain reduction
- Peak, RMS, and hybrid detection
- Feed-forward behavior
- Auto/program-dependent release
- Sidechain detector high-pass and low-pass filters
- Sidechain audition
- Stereo linking control
- Dry/wet mix
- Output gain
- Optional automatic gain compensation

2. Volume Curve Engine
- User-drawable gain envelope
- Bezier or tension-adjustable curve segments
- Nodes that can be added, moved, or removed
- Grid snapping
- Straight, curved, stepped, and ramp segments
- Tempo divisions from 1/64 note through multiple bars
- Straight, dotted, and triplet values
- One-shot, looping, and audio-triggered modes
- MIDI note triggering where supported
- Sample-accurate phase and retrigger behavior
- Trigger threshold
- Retrigger hysteresis
- Minimum retrigger interval
- Pre-delay and post-delay
- Attack, hold, and recovery timing
- Anti-click smoothing
- Free-time millisecond mode
- Host transport synchronization
- Correct behavior when playback starts in the middle of a bar

3. Spectral Ducking Engine
- Analyse the sidechain spectrum
- Attenuate frequency regions in the destination that collide with it
- Adjustable spectral resolution
- Frequency-range selection
- Maximum attenuation
- Spectral smoothing
- Time smoothing
- Attack and release behavior
- Broadband-to-spectral blend
- Preserve-body control to prevent over-thinning
- Tonal-versus-transient sensitivity
- Artifact protection
- A “Collision Map” representing meaningful overlap between the destination and sidechain, rather than blindly applying an inverted sidechain spectrum

Use a stable STFT overlap-add design with proper windowing and reconstruction. Add latency only when required and report it correctly to the host. Avoid phase discontinuities, zipper noise, musical noise, denormals, and invalid floating-point output.

MULTIBAND AND CHANNEL PROCESSING

Implement:

- One-band broadband mode
- Three-band mode with draggable crossovers
- Per-band depth, attack, release, and enable/bypass
- Stereo linked mode
- Adjustable channel linking
- Left/right mode
- Mid/side processing
- Ability to preserve mono low frequencies
- Per-band processing without crossover gaps or large response errors

Use suitable complementary crossover filters. Verify the recombined bands remain close to unity when no processing is occurring.

TRIGGER SYSTEM

Support:

- External sidechain input
- Internal input
- MIDI note
- Host transport/tempo
- Manual GUI test trigger
- Peak, RMS, transient, and frequency-weighted detection
- Trigger filter with audition
- Trigger threshold and hysteresis
- Trigger history and visual trigger markers
- Lookahead where enabled
- Negative timing only through properly reported lookahead latency

Architect the routing layer so additional trigger sources could be added later. Because DAW support for multiple sidechain buses is inconsistent, prioritize one dependable external sidechain bus. Do not create an unreliable multi-bus implementation. Document how a future companion Sender plugin could extend this.

LATENCY AND QUALITY MODES

Provide:

- Live: zero or minimal latency; compressor and curve processing
- Studio: moderate lookahead and efficient spectral processing
- Spectral: higher-resolution frequency-dependent processing
- Render: highest-quality configuration suitable for offline rendering

Changing modes must update reported latency safely. Do not allocate memory or rebuild large DSP structures directly inside the real-time audio callback.

COLORFUL AUDIO ANIMATION

Create a smooth, colorful, real-time central visualization showing:

- Destination waveform
- External sidechain waveform
- Gain-reduction envelope
- Trigger markers
- Input and sidechain spectra
- Spectral collision regions
- Frequencies currently being attenuated
- Optional removed-signal/delta spectrum

Suggested visual language:

- Destination: cyan/blue
- Sidechain: orange/magenta
- Collision energy: yellow/red
- Gain reduction: violet
- Output: green

Use gradients and restrained glow effects, but maintain readability. Animation should feel fluid and musical rather than decorative.

Critical performance requirements:

- The audio thread must only write lightweight analysis data into lock-free FIFOs or atomics.
- Rendering and FFT visualization must happen outside the audio thread.
- Preallocate visualization buffers.
- Limit GUI repaint rate to approximately 30–60 FPS.
- Decimate waveform data appropriately.
- Provide a reduced-animation or visualization-disable option.
- The plugin must continue processing correctly when its editor is closed.
- GUI activity must not materially increase audio-thread load or cause dropouts.

REAL-TIME SAFETY

Inside processBlock and any directly called audio-processing function:

- No heap allocation
- No file access
- No locks or blocking calls
- No GUI calls
- No logging
- No container resizing
- No unsafe object destruction
- No uncontrolled exceptions

Prepare buffers and DSP structures in prepareToPlay. Handle mono, stereo, missing sidechain, changing block sizes, sample-rate changes, transport discontinuities, bypass, and offline rendering safely. Silence, NaN, infinity, and extremely loud input must not destabilize processing.
